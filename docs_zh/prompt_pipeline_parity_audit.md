# Prompt Pipeline 对等审计

本次审计从第一性原理角度比较 EdgeCrab 的提示管道与 Hermes：

1. 实际发送到模型的字节是什么。
2. 压缩何时触发。
3. UI 声称的提示压力是什么。
4. 缓存的提示质量是否在会话恢复之间保持。
5. 工具和技能可用性是否在提示中真实反映。

## 本补丁集修复内容

### 1. 会话恢复现在保留缓存的系统提示

问题：
恢复的 EdgeCrab 会话丢弃了持久化的 `system_prompt`，强制在下一回合重新构建。这破坏了缓存连续性，并使恢复的会话比 Hermes 更昂贵、更不确定。

修复：
`Agent::restore_session()` 现在重用来自 SQLite 的持久化提示快照。

为什么重要：
提示缓存命中只有在前缀保持字节稳定时才有效。在恢复时重新构建提示是结构性可靠性错误，而不是表面优化问题。

### 2. 压缩现在是模型感知的

问题：
压缩检查使用 `CompressionParams::default()` 和硬编码的 `128_000` 窗口，即使活动模型具有不同的上下文长度。

修复：
`CompressionParams::from_model_config()` 从 `ModelCatalog` 解析运行时模型上下文窗口，并应用配置的阈值、目标比率和受保护的尾部。

为什么重要：
压缩阈值必须相对于真实模型限制表达，否则警告和压缩行为会在不同提供程序之间漂移。

### 3. 压缩压力现在估计完整请求，而不仅仅是聊天历史

问题：
EdgeCrab 仅在决定是否压缩之前从 `session.messages` 估计令牌。这忽略了：

- 缓存的系统提示
- 工具模式

修复：
对话循环现在在 API 调用之前从组装的请求有效载荷估计请求压力。

为什么重要：
模型只看到完整请求。任何忽略固定提示质量的预检检查都会低估压力并压缩得太晚。

### 4. 技能摘要过滤现在连接到真实的提示路径

问题：
主要对话路径调用 `load_skill_summary(..., None, None)`，因此按工具和工具集进行的条件技能激活在生产中实际上被禁用了。

修复：
实时管道现在传递：

- 活动工具名称
- 从真实注册表派生的活动工具集名称

为什么重要：
如果提示宣传了在当前工具配置中实际上无法运行的技能，代理会变得不太可靠，并且更有可能幻觉出能力。

### 5. 已知空工具可用性现在被视为权威

问题：
`skill_should_show()` 将 `Some([])` 视为"未知"，因此没有活动工具的会话仍然可以显示明确需要工具的技能。

修复：
条件技能评估现在区分：

- `None` => 可用性未知，保持宽松
- `Some([])` => 可用性已知为空，隐藏无法满足的要求

为什么重要：
此边缘情况直接影响受限环境、委托代理和无工具执行模式。

## 仍比 Hermes 重

EdgeCrab 在提示权重方面仍未完全达到 Hermes 的对等水平。

### 1. 上下文文件加载更广泛

EdgeCrab 目前通过工作树递归遍历 `AGENTS.md`。Hermes 更接近优先级优先的项目上下文选择。

影响：

- 更大的提示前缀
- 更多的缓存失效风险
- 在 monorepo 中冲突指令的可能性更高
- 目录之间的令牌波动性更大

残酷的事实：
这是 EdgeCrab 仍然比 Hermes 重的真正架构原因，即使在会计修复之后。

### 2. 提示组装功能更丰富但也更昂贵

EdgeCrab 注入的指导块比 Hermes 更多。有些现在是工具门控的，但基线提示仍然更广泛。

影响：

- 更强的内置行为塑造
- 更高的固定提示质量
- 恢复或委托会话更早达到压力的风险更大

残酷的事实：
EdgeCrab 当前更喜欢功能广度而不是前缀最小化。这是一个有意的权衡，但不是免费的。

## 可靠性立场

可靠性胜过原始提示丰富性。

正确的操作顺序是：

1. 构建真实的提示。
2. 保持前缀稳定。
3. 测量真实请求压力。
4. 在溢出之前压缩。
5. 在 UI 中展示运行时实际使用的相同语义。

其他任何方式都会设计出不稳定的行为。

## 测试矩阵

以下案例应保持覆盖：

### 单元测试

- 会话恢复重用持久化的 `system_prompt`
- 模型感知的压缩解析运行时上下文窗口
- 当存在系统提示或工具模式时，完整请求令牌估计增加
- 当可用工具已知为空时，技能条件隐藏工具门控技能
- 工具集派生对注册表匹配进行去重

### 集成测试

- 恢复的会话在下一回合保持提示前缀稳定
- 禁用的工具集从组装的提示中移除匹配的技能
- 委托/子代理会话仅公开其缩减工具集支持的技能
- `@context` 扩展使用模型感知的上下文限制
- 压缩警告和压缩触发基于完整请求压力，而非仅历史压力

### 模态和环境

- 具有完整核心工具的 CLI/TUI 会话
- 禁用工具的 CLI/TUI 会话
- 具有平台特定工具限制的网关会话
- 具有缩小工具集的委托代理会话
- 工具模式较大的执行代码重型会话
- 历史保持简短但固定提示质量较大的终端重型会话
- 重启后从 SQLite 恢复的会话

## 总结

EdgeCrab 现在在核心会计和缓存保留机制上与 Hermes 匹配：

- 提示压力显示语义
- 恢复时重用持久化提示
- 模型感知的压缩阈值
- 完整请求压力估计
- 实时路径中的条件技能过滤

EdgeCrab 在提示广度方面仍然超过 Hermes，这仍然是它感觉更重的主要结构性原因。如果严格对等是目标，下一个高价值更改是缩小递归上下文文件加载或对聚合上下文文件注入设置硬性预算。
